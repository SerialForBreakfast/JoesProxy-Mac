# JoesProxy 1.9.1 benchmark report, revision 7

## November 13, 2026 — optimized 60-minute rehearsal

JoesProxy completed 441 cycles in 3,603.6 seconds. The synthetic origin received 11,278 requests. The origin used port 41000 and the proxy used port 41100. The run recorded zero invariant failures, zero 502 responses and zero upstream self-connect notices. Both status-count workflows returned the correct answer in all 441 paired comparisons. The low-port result supports the port-collision hypothesis. The cause of the earlier intermittent 502s remains unconfirmed.

| Status-count workflow on this Mac | Median RPC bytes | Median workflow latency |
|---|---:|---:|
| Page through search results and calculate by ID | 8,834 | 37.3 ms |
| Filter and calculate locally | 1,315 | 11.7 ms |

The local calculation used 85.1% fewer median RPC bytes for this question. In the separate concurrent live-query exercise, 1,574 attempts succeeded and 190 returned `source_changed` as capture advanced. Those outcomes need to be counted when measuring end-to-end agent usage.

These measurements describe the optimized development checkout used for the rehearsal. The next eight-hour soak is deferred.

## November 13, 2026 — subscription-token experiment (revision 2)

For a 300-request window, Flash Low used **62.2% fewer reported total tokens** to count status codes with build 25. This is the median within-pair reduction across the four pairs where both versions produced a correct answer and completed the recorded MCP workflow. Asking for one inspected example reduced tokens by **54.0%** across three qualifying pairs.

| Frozen question | Correct answer and exact MCP sequence, 1.9.0 → build 25 | MCP calls in a complete workflow | All five attempts, median total tokens [min–max], 1.9.0 | Build 25 | Median paired reduction [eligible pairs] |
|---|---:|---:|---:|---:|---:|
| Count 502s and missing statuses | 4/5 → 5/5 | 3 → 1 | 50,821 [21,415–50,864] | 19,231 [19,224–19,239] | 62.2% [4] |
| Count and inspect one 502 | 3/5 → 5/5 | 4 → 3 | 53,719 [23,478–55,927] | 24,753 [24,751–27,151] | 54.0% [3] |
| Identify the functional JSON change | 5/5 → 3/5 | 2 → 1 | 22,272 [20,224–22,275] | 19,871 [19,866–19,876] | 10.8% [3] |

**Method.** Five pairs per question, alternating which version ran first. Every attempt started a fresh AGY 1.3.1 conversation with the signed-in subscription, model `gemini-3.8-flash-low`. Each arm used synthetic responses recorded by its own JoesProxy app-hosted MCP integration test. A local replay server verified tool name, arguments, order and completion. The prompt supplied the workflow and exposed its tools. This measures guided agent execution; autonomous discovery requires a separate experiment. The previous release used its 100-row page limit and reused a returned ID for the example. Both arms had equivalent disclosure permissions. The grading key was kept outside the prompt.

**Grading.** The count had to match 299 status-502 responses and one missing status. The example also needed a verified request ID, status and path. For the comparison we accepted equivalent field paths and an explicit indication of complete coverage. The frozen oracle requires Boolean values. Two build-25 answers correctly named the change but returned the strings `"false"` and `"true"`. They failed the typed-answer check. Three old-version count/example attempts failed to complete the exact replay sequence and returned wrong or incomplete answers. All five attempts per arm contribute to the displayed token distributions. Only pairs where both arms passed contribute to paired savings.

**Accounting.** The 30 measured attempts used 866,252 AGY-reported total tokens. Per-attempt input, output, thinking and cache-read counters are preserved as returned. Cache-read counts can exceed reported input and are not added to AGY's total. Setup probes are excluded. Sample sizes are small, and repeated prefixes may benefit from provider caching. Results apply to this model, prompt, client and workload. The workload-specific 85.1% figure above measures RPC bytes in the separate hour-long rehearsal.

## Revision 3 — typed Boolean comparison retest, November 13

The earlier comparison brief identified Boolean types but supplied the values as text previews. Two of five candidate answers repeated those strings. The revised brief supplies visible Boolean scalars as native JSON in `beforeValue` and `afterValue`. The overlapping string previews are omitted. Consumers of Boolean previews should use the typed fields. Redacted values keep the redaction preview.

We repeated only the comparison question with five fresh pairs, the same frozen question, model, replay recipe, and alternating order. The original 30-trial experiment above remains the record for the original build. The candidate retest used the changed 1.9.1 build-25 development source. All ten trials used the subscription. **Why the two correctness rows differ.** Three fixed-build answers named the right timestamp in a one-element array or structured list. Revision 2 recognized a string for that noise field. Accepting those equivalent noise descriptions is an additional semantic analysis. It does not change the frozen grade.

Under semantic review, all five rerun pairs qualify and their median paired reduction is **10.5%**. ## Revision 4 — autonomous debugging, November 13

Flash Low correctly diagnosed **15/15 cases on each version**, including all timestamp-only and missing-body controls. Build 25 consumed **568,392 total subscription tokens**, compared with **609,899 on 1.9.0**. That is 41,507 fewer tokens (6.8%) across these runs. Both versions completed 82 MCP calls. Median usage per investigation was 39,367 → 36,873 tokens; ranges were 33,736–48,331 and 27,511–63,155, respectively.

| Case | 1.9.0 correct | Build 25 correct | 1.9.0 total tokens for three runs | Build 25 total |
|---|---:|---:|---:|---:|
| Boolean enabled → disabled | 3/3 | 3/3 | 122,744 | 111,392 |
| String "false" → Boolean true | 3/3 | 3/3 | 121,833 | 112,236 |
| Numeric retry limit 1 → 0 | 3/3 | 3/3 | 120,380 | 109,695 |
| Timestamp change only | 3/3 | 3/3 | 118,408 | 105,593 |
| Second response body missing | 3/3 | 3/3 | 126,534 | 129,476 |

**Wire contract.** A separate authenticated MCP integration test inspected the decoded JSON-RPC result. Visible Booleans were native JSON Booleans. String "false" → "true" retained string previews. A string → Boolean transition preserved the type on each side. Numeric 0 → 1 reported number types with text previews. The sensitive Boolean exposed only redacted previews and no typed values. These assertions passed before inference began.

**Experiment.** The versions were 1.9.0 (23) and the modified development build 1.9.1 (25). AGY CLI 1.3.1 used gemini-3.8-flash-low with subscription authentication. We froze five cases, one question and the grading rubric before running them. Each fresh conversation had two chronologically ordered synthetic GET responses and five read-only tools exposed by the tested version. The agent received no tool sequence, request IDs or expected values. A workspace MCP adapter passed agent-selected tool names and arguments to the version's authenticated production dispatcher through a synthetic XCTest host. Timings and provider counters include tool discovery, argument selection, follow-ups and final answers. Raw AGY cache-read counters are recorded separately from its total. The grader checked the verdict, both cited request IDs, typed values for functional changes, and absence of invented changes for controls. The usage figures include all 30 attempts.

**Tool selection.** The earlier version used session_summary 44 times and response_evidence_brief eight times; build 25 used them 14 and 38 times respectively. Comparison briefs were requested 14 and 15 times. All 164 MCP calls succeeded. AGY also reads its local schema files. Four baseline trials and one candidate trial additionally invoked a shell directory listing of that server's schema folder. Those actions are flagged separately in the evidence; the listing reveals tool names, not fixture answers.

**Interpretation.** The guided comparison results above remain separate. The autonomous runs found the same answers on both versions and consumed more tokens on the candidate for the missing-body case in aggregate. Three repetitions, shared provider caching and serial execution of the candidate arm before the baseline arm limit the precision of any savings claim. This measures the five available read-only diagnostics in a synthetic environment.

## Revision 5 — when local aggregation pays off

**A 400-request status histogram used 72.8% fewer AGY-reported total tokens in the median paired comparison.** Both versions produced the correct answer in every run. The agent's question was to count each HTTP status, including missing responses, for GET video-segment requests inside a time window. The 400-request answer was 260 status 200, 60 status 206, and 20 each for 304, 404, 503 and missing. The input was synthetic HTTP metadata with a fixed periodic distribution and no padded bodies.

**Selection.** We deliberately chose a favorable workload: an exact many-row question with a fixed six-group answer. We varied the window size, kept a one-request control, and repeated 400 rows at a different offset. This characterizes a scaling mechanism; it does not estimate typical savings across proxy questions. Revision 4 retains the autonomous two-response result.

| Requests in window | 1.9.0 MCP calls | Build 25 calls | Warm transcript tokens, 1.9.0 → build 25 |
|---:|---:|---:|---:|
| 1 | 1 | 1 | 231 → 265 |
| 20 | 1 | 1 | 1,746 → 336 |
| 100 | 1 | 1 | 8,130 → 336 |
| 400 | 4 | 1 | 32,685 → 336 |
| 1,200 | 12 | 1 | 98,344 → 337 |
| 400, shifted window | 4 | 1 | 32,751 → 336 |

Both real version-specific MCP test hosts returned the oracle histogram in every window. The older arm reads minimal status rows in 100-row pages, with no individual body reads. The new arm applies the same filter and groups by status on the Mac. Local counts use tiktoken 1.0.20, o200k_base, one canonical call and structured answer per exchange. They exclude discovery, repeated context and inference.

**Subscription confirmation.** Three fresh guided pairs per window, alternating version order, using gemini-3.8-flash-low and the synthetic MCP replay server. The prompt supplied the workflow and arguments, never the histogram. Grade required the exact integer count for every group, exact MCP arguments and exhausted pagination. All 12 attempts returned AGY usage. Reported totals include agent overhead. This is a guided scale test, distinct from autonomous discovery.

| Window | Correct & complete, old → new | All-attempt median reported tokens [range], 1.9.0 | Build 25 | Median paired reduction on complete, correct pairs |
|---|---:|---:|---:|---:|
| Shifted 400 | 3/3 → 3/3 | 79,647 [79,599–82,675] | 21,659 [21,649–21,677] | 72.8% (3 pairs) |
| 1,200 | 1/3 → 3/3 | 40,959 [33,922–94,215] | 21,656 [21,655–21,659] | 77.0% (1 pair) |

At 1,200 rows the two incomplete baseline workflows used fewer tokens than the successful baseline because they stopped without completing the exact 12-page replay. Their smaller totals remain in the distribution. The 400-row result is the stronger public example. The local one-row result illustrates the overhead of returning an aggregate for a single record.

## Revision 6 — autonomous 400-request histogram

With the same 400-request question and freedom to choose tools, Flash Low returned the exact histogram in **5/5** build‑25 runs and **0/5** on 1.9.0. **No autonomous pair had two correct answers, so a paired token-savings percentage is unavailable.** The guided 72.8% result above applies to the supplied workflow.

*MCP counts are requests received by the test dispatcher; AGY schema reads, local commands and denied workflow actions are tracked separately. Each old-version trial made one search and then requested AGY's general workflow-execution permission. Headless AGY denied that action and returned an empty answer. The guided control demonstrates that 1.9.0 can obtain the answer by paging. The smaller autonomous baseline total reflects early termination.

The candidate requested capture_calculate in three runs and paged through sessions in all five. Its autonomous median was 3.47 times its guided median. AGY also attempted local commands, including inspecting and processing its own MCP output files. Two recursive search attempts exited unsuccessfully. This experiment constrains which MCP tools are authorized; AGY's built-in tooling and headless permission behavior also affect the result. Accuracy grades are for the final six counts and do not imply exclusive use of the aggregation operator.

**Protocol.** Frozen synthetic capture of 1,200 video-segment GETs, inclusive UTC window 00:11:11–00:17:50 on 1970-01-01. Oracle: 260 status 200, 60 status 206, 20 each of 304, 404, 503 and missing. Ten fresh subscription-only conversations, gemini-3.8-flash-low, five pairs alternating version order. Prompt gave the predicate, window and required answer shape. No page limit, arguments, tool name, expected counts or call sequence was supplied. Four read-only MCP tools exposed through the actual version-specific dispatcher: sessions_list, sessions_search, session_summary and capture_calculate. All ten attempts have usage receipts, including the five empty answers. Aggregate usage was 173,728 tokens for 1.9.0 and 389,008 for build 25.
